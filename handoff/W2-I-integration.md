## Required behaviour
1. `workflows/incident.ts`: one `"use workflow"` function `incidentWorkflow(incidentId, runId)` calling `"use step"` functions for SPEC §2 steps 1–8: collect (`collectRunArtifacts`), triage (`triage` + persist `decisions` row), diagnose (`selectAgents` → `runDiagnosis`), fix (`getRepoSnapshot` → `materializeRepo` → `runFix`), verify (`createVerifier().verify`; on fail one retry of fix with the verify output, then `needs_human`), propose (branch `rerun/fix-<runId>`, `commitFiles`, `openPullRequest` with `renderPrBody`; draft + `needsHuman` when `route()` = `draftPr`), await (workflow hook/webhook or sleep-poll on an `approved` flag set by the approve route — use the Workflow SDK's hook/`createWebhook`/`sleep` primitives as documented for the pinned version), confirm (`watchForNextRun` → `resolved`, or a new linked incident with `parentIncidentId` on `errored`). Each step sets `incidents.status`, appends `IncidentEvent`s via `appendEvent` (kinds/steps per SPEC §6/W1-E's seed so the UI renders real runs identically to the seed), stores artifacts (`log`, `plan_json`, `diff`, `verify_output`, `pr_body`), and accumulates cost (`summarizeIncidentCost`).
2. **Idempotency per `(incidentId, step)`**: a step that already completed (status event recorded) returns its stored result instead of re-running (no second PR, no second branch). Test it by invoking the workflow twice / replaying a step.
3. `startIncident(runId)`: dedupes on `runId` (one incident per run), creates the incident row, starts the workflow. Used by the poller, the webhook and the evals.
4. `src/poller.ts`: every `RERUN_POLL_SECONDS` (0 = off) calls `pollErroredRuns` on `RERUN_WORKSPACE` and `startIncident` for new errored runs; started once per server process (guard against Next dev double-init); not started in demo mode unless `RERUN_DEMO_AUTOPLAY=1`.
5. Webhook `POST /api/webhook/tfc`: HCP Terraform generic notification payload; 404 unless `TFC_WEBHOOK_SECRET` is set; verify `X-TFC-Notification-Signature` (HMAC-SHA512 of the raw body) with constant-time compare; accept only `run:errored` for `RERUN_WORKSPACE`; responds 202 and calls `startIncident`. Unit-test signature good/bad/missing.
6. Approve `POST /api/incidents/[id]/approve` → only from `awaiting_approval` or `needs_human` with an open PR → if draft, mark ready → `mergePullRequest` (squash) → status `merged` → resume the workflow's await → `confirming`. Request changes `POST .../request-changes` `{comment}` → `commentOnPullRequest` → `needs_human`. Exact bodies must match what W1-E's buttons send. 409 on wrong state.
7. Demo mode end-to-end: `npm run demo` starts the in-process mock MCP server, uses the recorded decision provider, `FakeVerifier`, fake GitHub, and on startup (if the DB has no incidents, or with `--fresh`) triggers `startIncident` for the recorded `apply-time-exit-1` run so a real workflow run populates the dashboard in demo mode (in addition to `seed:demo` data if W1-E's seed is used). Agents in demo mode: use a scripted mock model (`ai/test`) that replays a recorded agent transcript per scenario from `fixtures/scenarios/<name>/agents.json` (create these for at least `apply-time-exit-1` and `undeclared-reference`), so the Trace shows realistic tool calls with zero credentials.
8. Playwright `test/e2e/demo.spec.ts`: starts the demo, waits for the `apply-time-exit-1` incident to reach `awaiting_approval`, opens `/incidents/<id>`, asserts Trace steps, two Subagent panels (or one, per `selectAgents`), the diff, the verification Terminal and an enabled Approve button; clicks Approve and sees `resolved` (fake GitHub + mock MCP returns an `applied` next run). Runs in the existing `e2e.yml` workflow.
